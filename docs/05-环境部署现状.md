### 3.1 关键坑与解法（已解决）

| 阻塞 | 根因 | 解法 |
|---|---|---|
| Node 18+ 全部跑不起来 | 宿主 **glibc 2.27**，标准 Node 要 2.28 | 用 `unofficial-builds` 的 **glibc-217** 构建 |
| `dsh --version` 静默退出 0 | DSH 入口用 **`import.meta.main`**，该 API 需 **Node ≥ 24.2** | 从 Node 22 升到 **Node 24.21.0** |
| Ollama 二进制跑不起来 | 同样要 glibc 2.28 | **在 PRoot 内运行**（glibc 2.35） |
| PRoot 里看不到 GPU | 缺 `libcuda.so` | 用 `LD_LIBRARY_PATH=/opt/nvidia-driver`（codex 已 staging 驱动库） |
| llama.cpp CUDA 编译失败 | ① 系统 gcc 7.5 编不过 C++17/AVX512；② master 的 FP8 `cvt` 需要 **sm_90**，而 L40S 是 **sm_89**，CUDA 11.8 不支持 | 在 PRoot 内用 **gcc-11** 编译，并**关闭 CUDA** 只留 CPU 版；GPU 服务改由 Ollama 承担 |
| GitHub `git clone` 超时 | github.com:443 被墙 | **codeload.github.com 可达**（tarball 下载正常）；GitHub Release 直链也可达 |

## 5. 上下文容量测算（KV cache 数学）

约束：可用 47.5 GiB；保留 1.5 GiB 给计算图。

| 模型 | 权重 | KV/token | @原生 合计 | @64k | @131k |
|---|---:|---:|---:|---:|---:|
| Qwen3.5-0.8B | 0.50 | 0.047 | **12.5** (@262k) | 3.5 | 6.5 |
| MiniCPM5-2B | 1.45 | 0.041 | **6.7** (@131k) | 4.1 | 6.7 |
| Granite 4.2 3B | 2.09 | 0.156 | **22.1** (@131k) | 12.1 | 22.1 |
| Qwen3-8B | 4.68 | 0.141 | **10.3** (@40k) | 13.7 | 22.7 |
| Qwen3-32B | 18.4 | 0.250 | **28.4** (@40k) | 34.4 | **50.4 ❌** |

- **所有候选都能装下自己的原生上下文。**
- **Qwen3-32B 上 131k 需要 KV 量化**（q8_0 → 18.4+17.0 = 35.4 GiB ✅）
- **KV 开销由 `层数 × KV heads` 决定，不由参数量决定**：MiniCPM5-2B 每 token 比 Qwen3-32B 便宜 **6 倍**

### 6.3 未决的集成问题 ⚠️

**Qwen3 是思考模型，Ollama 把思考放进独立的 `reasoning` 字段，导致 `content` 为空。**

实测（`qwen35-08b`，`max_tokens=64`）：

| 请求方式 | content | reasoning_len | completion |
|---|---|---|---|
| baseline | `''` | 219 | 64 |
| `think:false` | `''` | 246 | 64 |
| **`reasoning_effort:"none"`** | **`'WAITER'`** | **0** | **3** |
| `chat_template_kwargs:{enable_thinking:false}` | `''` | 228 | 64 |
| prompt 加 `/no_think` | `''` | 211 | 64 |

**只有 `reasoning_effort: "none"` 能真正关掉思考并让 `content` 有内容。** DSH 的 `openai-completions` 适配器读 `content`，所以必须让本地端点关掉思考，或配置 `compat` 让适配器识别 reasoning 通道。**这是接入前必须解决的最后一公里。**
