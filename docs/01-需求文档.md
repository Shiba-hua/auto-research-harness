# 01 · 需求文档

## 1. 目标

在 `L40S-1-gpu`（单卡 L40S 48GB，2×Xeon 8352V / 144 线程 / 502GB RAM）上部署一套 harness 服务，它承担两件事：

1. **监听与调度云服务器上的 RLVR 实验**（一般功能）
2. **跑完 codex 未竟的事业，并在 GitHub 创建新分支报告结果**（★ 最高优先级硬需求）

用户明确：**其他一般功能可以不做，但第 2 项必须完成。**

## 2. 核心设计原则

> **不是执行一份硬编码任务列表，而是能够通过读取任务书、读取仓库现状、以及和用户交谈，自己弄明白该做什么。**

这条原则决定了性质：harness 必须是一个**有自主性的研究型助理研究员**，而不是一个队列执行器。

## 3. 角色与边界

| 角色 | 职责 |
|---|---|
| **codex（离线作者）** | 已交付：协议、配方、队列、源码、证据规范。不再在线 |
| **harness（本系统）** | 读懂现状 → 推断缺口 → 识别阻塞 → 提出方案 → 执行 → 验证 → 报告 |
| **人类（用户）** | 下达任务、审批、验收、可随时干预队列 |

**harness 不做的事**：
- 不判定"性能显著提升"这类科学结论（只报数字与统计量，由 `accept_project.py` 机器判定 + 人验收）
- 不修改宿主驱动 / 内核 / 硬件设置
- 不删除任何数据集
- 不把负结果粉饰成正结果

## 6. 自主性与审计（D3 展开）

harness 被授权自主行动，但必须沿用 codex 建立的证据规范。以下不变量来自 codex 的 130 个 commit，**不可违反**：

1. **不覆盖**：任何 run 的输出目录一经生成不再改写；失败换序号重跑（`-002`、`-003`、`-failure-001`）
2. **不删失败**：失败的运行、被拒的方案、无效的尝试全部保留
3. **哈希锁定**：recipe / 数据 / 模型 / launcher 的身份以 SHA256 记录
4. **源码干净**：`train.py` 在源码 dirty 时直接拒绝训练
5. **prospective ≠ executed**：计划文件自标状态，不得把计划说成结果
6. **显式声明未完成**：`acceptance.json` 带 `limitations[]`

harness 的**自主输出**应写成 `proposals/`（新配方提案）而不直接执行；执行前需过用户或 codex 的确认。

## 7. 基线保护（D4 展开）

在 harness 开始动手前，必须完成：

| 步骤 | 内容 |
|---|---|
| 1 | 在 codex 当前 HEAD（`7451cb1`，分支 `codex/experiments`）上打**基线 tag** |
| 2 | 提交或归档 284 个未跟踪 artifact（3.60 GiB），使基线自洽 |
| 3 | 配置 GitHub remote（**当前仓库没有任何 remote**），把基线推送到远端 |
| 4 | 从基线开**新工作分支**，harness 只在新分支上操作 |
| 5 | 保留 PRoot 运行时（`launcher_sha256` 被队列钉死，17 GiB） |

这样即使 harness 把工作区搞坏，也能从远端基线完整恢复。

## 8. 验收标准

| 项 | 标准 |
|---|---|
| 速记法路线 | 96/96 审计点齐备，**或** 有明确的负结果报告 + 阻塞原因 |
| 图表 | 6 张主图（3 类 × 2 领域）PNG/SVG 全部生成且通过视觉检查 |
| 报告 | GitHub 新分支含配方、指标、图表、阻塞说明，标注非 codex 推送 |
| 证据 | 284 个原有 artifact 全部提交，无丢失 |
| 服务 | DSH 可长期运行、可对话、可执行实验调度 |
| 纪律 | 全过程不改驱动、不删数据集、不覆盖历史 run |
