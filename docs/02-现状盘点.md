### 5.3 ★★ 速记法路线不是"未执行"，是"卡住"

**这是整个任务里唯一的真正研究性问题。**

#### 失败证据

`gsm8k-shorthand-v4-preflight-gpu-001`：
> **结论 FAIL，不支持全量 1024。** 32 requested/generated、**3 retained、29 excluded**，全部 32 题审读结论 FAIL。`semantic_equivalence_verified = false`

#### 根因（codex 已精确诊断）

| 输出阶段 | 实际 tokens | 占比 |
|---|---:|---:|
| 已闭合 thinking 的前缀 | 14,160 | |
| thinking-end 边界 | 29 | |
| **thinking 结束后的 JSON 阶段** | **86,998** | **76.67%** |
| 未闭合 thinking | 12,288 | |
| 合计 | 113,475 | |

**8B 教师模型在结束思考后进入 token 退化循环**：
- 24 条 JSON 截断中 23 条有精确连续 token 块循环
- 固定检测规则（周期 1–64 tokens、至少 4 次连续）覆盖 **67,014 个 token = 该阶段的 77.03%**
- 实例：`"principle":"N"` 与 `0,` **循环 1679 次**；源索引 33 重复 **814 次**；一条在 principle 字符串里从行号 1 枚举到约 696

#### codex 做过的排查

怀疑是请求级 guided decoding 导致，于是构造了 `unguided` 诊断（只移除 `guided_decoding`，其余全不变）：

```
status = "generation_complete_release_pending"
counts = {selected:32, requested:32, generated:32, retained:4, excluded:28}
semantic_equivalence_verified = false
training_eligible = 永不可训练
```

**移除 grammar 后 retained 从 3 升到 4 —— 几乎无改善。退化不是 guided decoding 造成的。**

#### 数据目录不存在

```
data/gsm8k-coldstart-shorthand-001   MISSING
data/arc-coldstart-shorthand-001     MISSING
（对照：data/gsm8k-coldstart-cot-001 与 -cod-001 均 EXISTS）
```

而 SFT 配置要求 `expected_auxiliary_version: 4` + `require_provenance: true`。

#### 结论

**要完成任务，必须先解决"如何让教师模型生成不退化的速记法教学数据"**——需要读协议 → 读失败诊断 → 提出新方案 → preflight 验证。这没有任何现成队列能覆盖，**正是"不能是硬编码任务列表"的直接证据**。
