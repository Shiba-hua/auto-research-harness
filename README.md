# auto-research-harness

**在一台云 GPU 服务器上无人值守地推进一个既有研究纲领。**

这不是又一个"AI 科学家"。它是**运维层**：一个小模型 7×24 顶班，一个大模型按需进场，
所有写操作过安全闸，所有 GPU 争用有凭证 —— 让一个**已经存在的**研究项目在你不看着的时候继续往前跑。

> 定位说明：本项目**不自称"研究团队"**。它只有一个真正干活的研究员（32B），
> 加一个只负责路由与值守的小模型（2B），加一个审批插件。叫"团队"是过度声称。

## 三个角色

| 角色 | 模型 | 位置 | 职责 |
|---|---|---|---|
| **值班员** | MiniCPM5-2B · IQ4_XS · 12 线程 | CPU 常驻，:18099 | 只读查询、队列增删、绘图、确定性中止。**唯一的自主决策是"是否唤醒研究员"** |
| **研究员** | Qwen3-32B-AWQ · vLLM 0.10.2 | GPU 按需，:18001 | 跑实验、改代码、出图、写报告。被唤醒后自主执行 |
| **安全员** | 复用 MiniCPM5-2B | 挂在 `approval/request` 瀑布上 | 三态审批。**模型只能收紧，不能放松** |

DSH Web 监听 `:18080`。全部由 supervisord 托管。

## 三条核心设计决策

### 1. 确定性优先，模型不碰不可逆判断

中止实验、释放显存这类操作**不经过任何模型**：识别意图 → 回显代价 → 等确认 → 执行 → **返回凭证**。
凭证规则是双条件，缺一不发：

```
发凭证 ⟺ gpu_used_mib < 1000  AND  leftover_pids == 0
```

只看显存会漏掉"进程还活着但不占显存"的中间态。

### 2. 用 git 可逆性替代 shell 隔离

本机没有可用的 OS 级沙箱（无 bwrap、内核无 Landlock、seccomp 禁 user namespace），
所以**护栏不建在沙箱上**：

- **文件层**：`dsh-fs-sandbox` 进程内路径判定。lab 可读、只写工作区
- **命令层**：`guarded_bash` 三态 —— 白名单（纯只读）放行 / 黑名单拒绝 / **含管道重定向等元字符一律转审批**。故意不做聪明的 shell 解析，因为解析器本身会变成漏洞
- **改动层**：先打基线 tag 再提交，之后所有改动只能在专用分支。**禁用 `git worktree`** —— 若项目以 editable 方式安装，worktree 里的改动不会被 import，研究循环会静默失效

### 3. 审批瀑布：模型只能收紧

【通过】→ `allowed-once` ｜ 【需人工】→ `next()` 委托人类 ｜ 【拒绝】→ `rejected`

模型即使被绕过，最坏结果是**多问你一次**，而不是放行危险写入。非法返回值自动归 `unavailable`（fail-closed）。

## 实测数字（非估算）

| 项 | 值 |
|---|---|
| 研究员 40k 上下文 | **37,231 token 输入 → 正常回答**（`finish=stop`） |
| 研究员工具调用 | 首试命中，参数正确 |
| 研究员吞吐 | decode **38.6 t/s** · prefill **1,679.7 t/s** |
| KV cache | 98,848 token，40k 请求并发 2.41× |
| 显存 | 峰值 46,710 MiB / 48 GB |
| 显存释放 | **2 秒**归零，0 残留，凭证签发 |
| 值班员吞吐 | 44.5 t/s（CPU） |
| 命令护栏判定表 | **13/13 正确** |

## 量化选型：为什么是 4bit 而不是 8bit

| 方案 | 权重 | +KV@40k | 合计 | 48 GB 内 |
|---|---:|---:|---:|---|
| FP8 | 31.97 GiB | 10.0 | ~45–46 | ⚠️ 贴边，很可能 OOM |
| **AWQ 4bit** | **18.00 GiB** | 10.0 | **~31–32** | ✅ 余 ~15 GiB |

**8bit 在长上下文这一条上是更危险，不是更保险。**
质量代价（官方对比表）：LiveBench −1.8 · GPQA **+0.6** · MMLU-Redux −0.1 · AIME24 −2.0，**平均约 1%**。

## 部署

### 前置

- 一台有 GPU 的 Linux 服务器（本项目在 L40S / 48 GB 上验证）
- Node ≥ 22.13（本项目用 24.21）
- DeepSeek Harness（DSH）
- 一个 PRoot userspace（Ubuntu 22.04）—— 因为宿主 glibc 往往太旧

### 关键脚本

| 文件 | 作用 |
|---|---|
| `deploy/vllm-run` | 在 PRoot userspace 内起 vLLM（研究员） |
| `deploy/guard-run` | 在 PRoot 内起 llama-server（值班员） |
| `deploy/dsh-run` | 在 PRoot 内起 DSH —— **因为 `sharp`/`node-pty` 要 glibc ≥ 2.28** |
| `deploy/mcp/lab_server.py` | 13 个 lab 工具的 MCP 服务器（纯 stdlib，无依赖） |
| `deploy/cordis.patch.yml` | DSH profile 补丁：两条模型路由 + 研究员子代理 + MCP + 权限 |
| `deploy/supervisord.conf` | 三个服务的托管与存活策略 |
| `deploy/download-model.sh` | 模型下载（可续传，支持镜像端点） |
| `deploy/measure-researcher.py` | 研究员性能与能力测量 |

> ⚠️ `cordis.patch.yml` 里**新增条目必须放在 `insert:` 块中**。
> 裸 `- id: x` 只用于修改已存在的条目，写错了会静默失效。

## 边界与诚实标注

- **PRoot 不是安全边界**，它只是系统调用翻译
- 文件层围栏是 **containment，不是 security boundary**：它管得住"模型直接写文件"，
  管不住"模型写了个脚本、再由非受限进程执行它"
- 本机**没有**可用的 OS 级沙箱，所以命令护栏完全落在审批层
- 未验证：多并发下的稳定性、跨重启的确定性、长时间运行的内存增长
